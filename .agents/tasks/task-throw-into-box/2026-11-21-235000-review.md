# Strict-success throw policy, retrained, with real-arm pre-checks (v2)

Retrains the CEM throw policy under a strict success definition (ball leaves the gripper, is released at least 8 cm from the box centre, and rests in the box) and reports 72/100 on held-out box positions, down from the withdrawn 85. `run_throw.py --real` now checks the plan's simulated jaw-tip path against a keep-out, checks the arm is at the start pose, rejects boxes outside the trained range and e-stops on any exception. The docs state that the real path usually refuses and that Guard's step cap was not in training. All nine issues from the first pass are addressed or out of scope, except that the replay speed setting is still inconsistent with the sim.

Watch for: (1) real replay uses `speed=0.5` while the sim trained at `speed=1.0`, and `list_plan` prints "same timing as the sim" (confirmed, `run_throw.py`); (2) the horizon-truncation path counts a ball inside the box volume as success without requiring it to be at rest, contrary to the docs (confirmed, `throw_env.py` step); (3) the "throw" is a 9 to 13 cm lob just past the 8 cm threshold at about 0.84 m/s mean release speed, so 72% is a short-lob number (confirmed, `results/throw_eval.json`).

**Verdict**: APPROVED

## High-level view

The success metric now measures what the task asks for. Release must be detected, must happen 8 cm or more from the box centre, and the run continues until the released ball rests. The 72% figure is credible as a sim result, and the docs explain the earlier 85% withdrawal. The throw itself is modest: a lob of about 10 cm. Contact-impulse realism is still unverified.

The real-arm path is now gated by a plan keep-out check, a start-pose check, a trained-range check and an e-stop on any exception. It still cannot be expected to reproduce the sim: Guard's 0.35 step cap and the lower `speed` value change timing, and the gripper release is stepped by index, not by arm position. The docs say so and the default box is refused by the keep-out. The remaining defect is a printed claim about timing that is not true.

Team commits (MuJoCo twin, cup skill, `kin.py`, `station_backend.py`, `vision.py`, `.mcp.json`, `norma`, `autorun.py`) are not part of this change and were not reviewed. The missing-asset problem from pass one is resolved because the scene and hulls landed in a team commit.

## Timing mismatch between sim and real replay

The env calls `send_goals(..., speed=1.0)` every 100 ms and training happens at that setting. `real_run` calls `guard.move(..., speed=0.5)` at 10 Hz. `list_plan` prints that the replay has "same timing as the sim". The plan also asks for per-frame joint moves up to about 0.7 (0.95 for box (0, 0.38)), which Guard cuts to 0.35. Combined, the real arm trails the plan by a growing margin, and the gripper (exempt from the cap) opens on schedule. The docs already flag the step cap as the reason the real path will not transfer. The speed value is a separate, cheaper fix, and the printed claim should not say the timing matches.

## Success on truncation

On termination the success needs release, rest, in box and throw distance. On truncation (30 steps) it needs only `inbox and is_throw()`, where `in_box` is a position test. A ball still in flight or bouncing inside the volume at 3 s is counted, while the docs describe success as resting in the box. The effect on the 72% is probably small because most releases settle well before 3 s, but it is untested; the check is one line.

## Real-arm gating

The gating now refuses unknown start poses, out-of-range boxes and plans whose simulated tip drops below 3 cm or returns within 5 cm of the base. Per the docs the default box fails this check, so the path is mostly a refusal, which is the safe outcome. The keep-out is computed from the sim path only. On the real arm, lag from the step cap and the lower speed changes where the tip is, so the check cannot be treated as a guarantee. The gripper joint is excluded from the start-pose check, and `--with-ball` does not verify a ball is present.

## What 72% means

Release distances average 9.8 cm against a threshold of 8 cm, and the motion was found by CEM to be a jaw-open lob during the swing. Two further CEM rounds produced the same 72/100, so the box conditioning or the 10 Hz release timing is the cap. The 95% interval (about 63 to 80%) is stated in the docs and is in line with n=100. Dataset yield (82/100 on seeds 50000+) differs from eval (72/100) by an amount consistent with sampling noise.

## Test coverage

Not tested: `run_throw.py` gating (`--real` without `--i-have-a-human`, out-of-range box, start-pose refusal, exception e-stop), the truncation success path, and any real-arm behaviour. The smoke script covers env stepping only.
