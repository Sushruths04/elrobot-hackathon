# NormaCore Station - deep dive (from the source, v0.1.0-beta.10, repo head 2026-11-10)

Everything below was read from `github.com/norma-core/norma-core` (MIT). A copy lives in `vendor/norma-core-src/`.

## 1. What it is
A single Rust binary (`station`) that owns the hardware (USB servo buses, USB cameras, ...) and publishes everything
as **NormFS queues** (append-only logs with pointers). Clients (web UI, Python, Go) read/write queues over TCP.
- `station --web --tcp`  -> TCP/NormFS on **8888**, websocket+web UI on **8889** (`http://localhost:8889`).
- Config: `station.yaml` (drivers, inference queue). Data dir `./station_data` (2 GB queue cap by default).
- Languages: Rust (station, drivers), Go + Python (protobuf SDK "gremlin"), TypeScript (web viewer, Electron app).

## 2. Wire protocol (so you can write your own client in 30 lines if station_py misbehaves)
- Frames: `u64 little-endian length` + protobuf `normfs.ClientRequest`. First message `SetupRequest(version=1)`, then ping every 1 s.
- Ops: `enqueue(queue, bytes)`, `enqueue_pack`, `read_from_offset`, `read_from_tail`, **`follow(queue)`** (offset 0 from tail, limit 0 = stream).
- Python bindings are generated by `python3 shared/gremlin_py/gremlin.py` (pure Python, **no Go/protoc needed**) -> already done in `vendor/norma-core-src/target/gen_python/`.
- Import quirk: code does `from target.gen_python.protobuf...` and `from shared.gremlin_py...` => repo root must be on `sys.path` (normakit does this).

## 3. Queues that matter
| Queue | Content | Use |
|---|---|---|
| `st3215/inference` | `InferenceState`: per bus, per motor **full register dump** (`state` bytes), calibrated `range_min/max`, last command + result | joint feedback |
| `commands` | `StationCommandsPack{DriverCommand[]}` | **send motion** |
| `inference-states` | `InferenceRx`: pointers to the latest entry of *every* queue incl. `QDT_USB_VIDEO_FRAMES` (21) | discover camera queues |
| `usbvideo/<md5>` | `usbvideo.RxEnvelope{ET_FRAMES, FramesPack(JPEG or NCHW)}` | camera frames |
| `inference/normvla` | `normvla.Frame{joints[{position_norm, goal_norm, current_ma, velocity}], images[224x224 jpeg]}` | VLA policy I/O (SmolVLA) |
| `inference-tags/rx` | add/remove string tags on a state pointer | label episodes ("task=put waffle in box") |

## 4. ST3215 servo control (what `move` really is)
Registers (from `protocol/memory.rs`): `0x28` torque enable (1B), `0x29` acceleration (1B), **`0x2A` goal position (2B LE, 0-4095)**,
`0x2C` goal time, **`0x2E` goal speed (2B)**, `0x30` torque limit, `0x38` present position (sign-bit quirk: bit15), `0x3A` speed,
`0x3C` load, `0x3E` voltage (0.1V), `0x3F` temp, **`0x45` current (mA)**.
Commands: `write`, `reg_write`+`action` (buffered, synchronous start), **`sync_write`** (many motors one packet), `auto_calibrate`, `freeze_calibration`.
Each motor has a station-calibrated arc `range_min/max` -> normalise: `norm=(pos-lo)/(hi-lo)`.
`current-threshold` and `deadband` in `station.yaml` are per-driver safety knobs.

## 5. Facts that change strategy
1. **Camera frames are downscaled to 224 px by default** (`usb-video.resize_target: 224`). Fine for a 224-px VLA, *terrible* for an LLM. Set `resize_target: 0` (full res) or 640. Most teams will not notice.
2. **Motor current is free telemetry** (`current_ma`): grasp success, collisions, stalls and "pressing on table" can all be detected without vision.
3. **ElRobot has an official URDF** (`hardware/elrobot/simulation/elrobot_follower.urdf`, 8 revolute joints `rev_motor_01..08`, limits in `normakit/core.py`). => forward/inverse kinematics, digital twin, workspace maps, collision-aware planning, all offline. Probably nobody else will use it.
4. **No MCP / LLM code exists in the repo** (grep: nothing). The track is greenfield. The AI example is only `software/ai/smolvla_py` (SmolVLA fine-tune; trainer is 6-DoF/CUDA, ElRobot has 8 servos -> needs a patch; Team Waffle did this in June).
5. **Control-authority is unsolved** (ADR 0009 "accepted, not implemented"): web UI controls and scripts can fight over the bus. Rule: close the browser's control panel while the agent drives; one writer at a time.
6. `yahboom-dogzilla-lite: mode: simulation` is the only "simulation" - a fake dog serial port, not physics.
7. Examples show the intended extension points: `arm2dog-py` (leader arm -> dog arm mirroring), `st3215-remote-teleop-py` (teleop over network), `so101-autocalibration-py`.
8. Station runs on **macOS ARM, Linux x86/ARM (Raspberry Pi)**. Dataset export: `bin/dataset-mp4`, `dataset-generator`, parquet export (`docs/datasets/export-parquet`) -> LeRobot v2.1 via the pizza-hackathon script.

## 5b. Hardware (ElRobot)
7+1 DOF, 430 mm reach, ~800 g, 8x ST3215 30 kg servos (12 V) on one Waveshare/Seeed bus board; leader arm 7.4 V back-drivable servos.
Two UVC cameras in the BOM: **wrist/arm camera** + **table camera**. 4 printable camera mounts (incl. a 28 mm gripper mount added 2026-11-10 -> they are actively working on wrist vision).
Gripper = motor 8, URDF range 0..2.2 rad, jaws via mimic joints.

## 6. Risks / unknowns to resolve in the first 30 minutes on site
- Which bus serial is the follower (leader may be on the same Station).
- Are cameras JPEG or NCHW? what resolution? (`normakit` handles both.)
- Is the arm already calibrated (`range_min < range_max` for all 8)? If not: `auto_calibrate` command / web UI.
- Does `norm -> URDF angle` (linear map over calibrated arc) match reality? Run `scripts/check_urdf_map.py` (TODO on site: move joint 2 to 0.25/0.75, compare sim vs photo).
